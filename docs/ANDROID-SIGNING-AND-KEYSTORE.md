# ABIZ LOCKER — Signing & Keystore Strategy

## STATUS: PRE-ENROLLMENT (no production devices enrolled yet)
## This document must be read BEFORE any production device enrollment.

---

## Critical Warning

> The Android Device Owner binding is tied to the signing certificate.
> Once a device is enrolled as Device Owner with a specific signing key,
> that same key MUST be used for all future APK updates.
>
> Changing the production signing key = factory reset of ALL enrolled devices.
> This cannot be recovered. It is irreversible.

---

## Keystore Types

### 1. Debug Keystore (Development Only)
- Location: `~/.android/debug.keystore` (auto-generated by Android SDK)
- Password: android
- Alias: androiddebugkey
- Key Password: android
- Validity: 30 years
- Use for: local builds, testing, ADB installs on dev devices
- DO NOT use for production enrollment
- APK ApplicationID: `com.abiz.locker.debug` (has `.debug` suffix added by build config)

### 2. Release Keystore (Production)
- Location: NEVER in the repository
- Location: Secure file storage (encrypted drive, CI/CD secret store)
- Use for: all production-enrolled devices
- APK ApplicationID: `com.abiz.locker` (no suffix)

## Generating the ABIZ Locker Release Keystore

IMPORTANT: Run this ONCE. Store the output keystore securely. Back it up.

```batch
rem Run from a secure directory (NOT the project folder)
rem Use JDK keytool from Android Studio JBR:

"C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair ^
  -alias abiz-locker-release ^
  -keyalg RSA ^
  -keysize 4096 ^
  -validity 10000 ^
  -keystore abiz-locker-release.jks ^
  -dname "CN=ABIZ Locker, OU=Android, O=ABIZ, L=Unknown, S=Unknown, C=PK"
```

When prompted:
- Set a strong keystore password (minimum 12 characters, alphanumeric + symbols)
- Set a strong key password (can be the same as keystore password)
- Record both passwords in a secure password manager (NOT in this file)

## Keystore Storage Strategy

### Development Phase (current)
- Use debug keystore only
- No production keystore needed until first real device enrollment
- Keep `keystores/` directory in .gitignore (already added)

### Production Phase
Option A (Local): Store encrypted keystore on encrypted drive. Backup to USB and offline storage.
Option B (CI/CD): Store as encrypted GitHub/GitLab CI secret. Use environment variables.
Option C (HSM): Hardware Security Module for high-volume deployments.

**For MVP**: Option A is sufficient. Move to Option B/C before scaling.

## Environment Variables for Release Build

```batch
rem Set before running: gradlew.bat assembleRelease
set ABIZ_RELEASE_STORE_FILE=C:\path\to\secure\abiz-locker-release.jks
set ABIZ_RELEASE_STORE_PASSWORD=<keystore-password-from-password-manager>
set ABIZ_RELEASE_KEY_ALIAS=abiz-locker-release
set ABIZ_RELEASE_KEY_PASSWORD=<key-password-from-password-manager>
```

NEVER:
- Set these in .env files committed to git
- Set these in shell profiles visible to others
- Hard-code them in build.gradle.kts

## Backup & Recovery

1. After generating keystore:
   a. Copy to USB drive (encrypted)
   b. Copy to secure cloud backup (encrypted zip)
   c. Record passwords in password manager
   d. Write passwords on paper and store in physical secure location (safe)

2. Verify backup can be opened before using for any enrollment

3. Test signing:
```batch
set ABIZ_RELEASE_STORE_FILE=backup-copy.jks
gradlew.bat assembleRelease
rem Verify APK signature:
"C:\Program Files\Android\Android Studio\jbr\bin\apksigner.bat" verify --verbose app-release.apk
```

## Build Configuration (agent-android/app/build.gradle.kts)

The build.gradle.kts reads signing config from environment variables:

```kotlin
// ABIZ signing config (reads env vars — no secrets in source)
create("release") {
    val keystorePath = System.getenv("ABIZ_RELEASE_STORE_FILE")
    if (keystorePath != null) {
        storeFile = file(keystorePath)
        storePassword = System.getenv("ABIZ_RELEASE_STORE_PASSWORD")
        keyAlias = System.getenv("ABIZ_RELEASE_KEY_ALIAS")
        keyPassword = System.getenv("ABIZ_RELEASE_KEY_PASSWORD")
    }
}
```

## Production Key Change Emergency Procedure

IF (and only if) the production signing key is lost or compromised:

1. STOP new enrollments immediately
2. Issue unlock commands to all enrolled devices while still possible
3. Notify shop owners of the situation
4. Factory reset all enrolled devices (they CANNOT be updated with new key)
5. Generate new keystore
6. Rebuild and sign APK with new key
7. Re-enroll all devices
8. Audit trail: document the incident

This is a catastrophic event. Prevention is the only cure.
